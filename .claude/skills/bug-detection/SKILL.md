# Bug 排查技能

## 技能定位
你是小边的技术助手，负责定期排查项目中的 Bug 和不合理设计。

## 排查范围

### 前端问题
1. **UI/UX 问题**
   - 页面白屏/加载失败
   - 布局错乱、响应式问题
   - 交互不流畅
   - 样式不统一

2. **功能问题**
   - 按钮点击无响应
   - 数据加载失败
   - 表单验证问题
   - 路由跳转错误

3. **性能问题**
   - 页面加载缓慢
   - 内存泄漏
   - 频繁重复请求
   - 大量控制台错误

### 后端问题
1. **API 问题**
   - 接口返回错误
   - 数据格式不一致
   - 权限控制缺失
   - 错误处理不当

2. **数据库问题**
   - 查询效率低
   - 数据不一致
   - 关联错误
   - 缺少索引

3. **逻辑问题**
   - 业务逻辑错误
   - 边界条件未处理
   - 并发问题
   - 数据验证缺失

### 代码质量问题
1. **重复代码**
   - 相同逻辑多处实现
   - 可复用的组件未抽取

2. **命名不规范**
   - 变量/函数命名不清
   - 文件名不符合规范

3. **注释缺失**
   - 复杂逻辑无说明
   - API 文档不完整

## 排查方法

### 第一步：全面扫描
```
检查项目 → 识别问题 → 记录详情
```

1. **运行项目** - 启动前后端服务
2. **访问页面** - 逐个测试主要功能
3. **查看控制台** - 记录所有错误和警告
4. **检查网络** - 查看失败的 API 请求
5. **测试边界** - 尝试异常输入和操作

### 第二步：问题分类
将发现的问题按严重程度分类：

| 等级 | 描述 | 示例 | 优先级 |
|-----|------|------|--------|
| 🔴 严重 | 导致功能无法使用 | 白屏、崩溃 | P0 |
| 🟡 中等 | 影响用户体验 | 加载慢、样式错乱 | P1 |
| 🟢 轻微 | 不影响功能 | 命名不规范、注释缺失 | P2 |

### 第三步：详细记录
对每个问题记录以下信息：

```
问题ID: BUG-001
发现时间: 2025-03-26
问题等级: 🔴 严重
问题类型: 前端/后端/数据库/代码质量

问题描述:
[具体描述问题现象]

复现步骤:
1. 访问页面 /reports
2. 未登录状态下
3. 页面显示白屏

当前状态:
[用户看到的是什么]

期望状态:
[应该看到的是什么]

相关文件:
- src/pages/ReportsPage.tsx
- src/components/AuthGuard.tsx

错误信息:
[控制台错误、API错误等]
```

### 第四步：生成问题列表
将所有问题整理成列表格式：

```markdown
## 排查问题列表

### 🔴 严重问题 (P0)
1. [BUG-001] ReportsPage 白屏问题
   - 位置: src/pages/ReportsPage.tsx
   - 现象: 非审核员用户访问白屏
   - 状态: 待审核

### 🟡 中等问题 (P1)
1. [BUG-002] API 错误处理不统一
   - 位置: src/api/*.ts
   - 现象: 错误信息显示不一致
   - 状态: 待审核

### 🟢 轻微问题 (P2)
1. [BUG-003] 变量命名不规范
   - 位置: src/components/Navbar.tsx
   - 现象: 部分变量名不够语义化
   - 状态: 待审核
```

- [ ] 网络请求是否正常
- [ ] 响应式布局是否正常
- [ ] 权限控制是否生效

### 后端检查清单
- [ ] 所有 API 是否能正常响应
- [ ] 数据库连接是否正常
- [ ] 权限验证是否完整
- [ ] 错误处理是否合理
- [ ] 数据验证是否充分
- [ ] 日志记录是否完整
- [ ] 并发处理是否正确
- [ ] 事务处理是否合理

### 代码质量检查清单
- [ ] 是否有重复代码
- [ ] 命名是否清晰规范
- [ ] 注释是否充分
- [ ] 函数是否过长
- [ ] 复杂度是否过高
- [ ] 是否有硬编码

- [ ] 类型定义是否完整

## 排查报告格式

完成排查后，生成报告提交给审核技能：

```markdown
# Bug 排查报告

排查时间: 2025-03-26
排查人员: 小边
排查范围: 前端 + 后端 + 代码质量

## 问题汇总
- 🔴 严重: X 个
- 🟡 中等: X 个
- 🟢 轻微: X 个
- 总计: X 个

## 详细问题列表
[按照问题分类列出所有发现的问题]

## 建议处理顺序
1. [BUG-001] - 严重度高，影响大
2. [BUG-002] - 中等优先，影响体验
3. [BUG-003] - 低优先，可延后处理

## 备注
[其他需要说明的事项]
```

## 自动化排查脚本

### 前端检查
```bash
# TypeScript 编译检查
npm run type-check

# 代码格式检查
npm run lint

# 单元测试
npm run test
```

### 后端检查
```bash
# TypeScript 编译检查
npm run type-check

# 代码格式检查
npm run lint

# 数据库迁移检查
npx prisma migrate status
```

## 排查频率建议
- **全面排查**: 每周一次
- **快速检查**: 每天一次（控制台错误、网络请求）
- **代码审查**: 每次提交后

---
**排查原则**: 全面细致、记录完整、优先级清晰
