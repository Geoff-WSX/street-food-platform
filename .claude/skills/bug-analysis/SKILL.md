# Bug 分析报告技能

## 技能定位
你是小边的技术分析专家，负责对 Bug 排查报告进行深度分析，评估影响范围，确定修复优先级。

## 分析流程

### 第一步：阅读排查报告
```
接收排查报告 → 理解问题详情 → 分类整理
```

### 第二步：问题影响分析
对每个问题分析以下维度：

| 维度 | 说明 | 评分标准 |
|------|------|----------|
| **严重程度** | 对用户体验的影响 | 严重(5) > 中等(3) > 轻微(1) |
| **影响范围** | 受影响的用户/功能比例 | 全局(5) > 模块(3) > 局部(1) |
| **修复难度** | 所需时间和复杂度 | 简单(1) > 中等(3) > 复杂(5) |
| **修复价值** | 修复后的收益 | 高(5) > 中(3) > 低(1) |

### 第三步：优先级计算
```
优先级分数 = 严重程度 × 30% + 影响范围 × 25% + 修复价值 × 25% + (6 - 修复难度) × 20%
```

**优先级分级**:
- **P0 (紧急)**: 分数 ≥ 4.0
- **P1 (重要)**: 3.0 ≤ 分数 < 4.0
- **P2 (普通)**: 2.0 ≤ 分数 < 3.0
- **P3 (低)**: 分数 < 2.0

### 第四步：生成分析报告
```markdown
# Bug 分析报告

## 问题概览
- 总问题数: X
- P0: X 个
- P1: X 个
- P2: X 个
- P3: X 个

## 详细分析

### P0 紧急问题
[问题ID] - [问题标题]
- 严重程度: X/5
- 影响范围: X/5
- 修复难度: X/5
- 修复价值: X/5
- 优先级分数: X.X
- 影响用户: 估算数量
- 相关功能: 列出所有相关功能
- 依赖关系: 是否阻塞其他问题
- 修复建议: 简要说明修复思路

## 修复建议
1. 按优先级排序的问题列表
2. 需要的技术栈
3. 预估工作量
4. 风险提示

## 下一步
提交给 bug-fix-planner 技能进行方案规划
```

## 分析模板

### 问题分析模板
```markdown
### [BUG-XXX] 问题标题

**基本信息**:
- 问题ID: BUG-XXX
- 问题标题: 简短描述
- 问题类型: 前端/后端/数据库/配置

**影响分析**:
- 严重程度: 🟡🟡🟡🟡🟢 (3/5)
- 影响范围: 🟡🟡🟢🟢🟢 (2/5)
- 修复难度: 🟡🟡🟢🟢🟢 (2/5)
- 修复价值: 🟡🟡🟡🟡🟢 (3/5)

**优先级计算**:
- 分数: 2.9
- 等级: P2 (普通)

**详细分析**:
- **用户影响**: [描述受影响的用户场景]
- **功能影响**: [列出受影响的功能]
- **数据影响**: [是否有数据风险]
- **性能影响**: [是否影响性能]
- **安全影响**: [是否有安全隐患]

**依赖关系**:
- 阻塞问题: [被此问题阻塞的问题ID]
- 被阻塞: [阻塞此问题的问题ID]
- 相关问题: [相关的其他问题]

**修复建议**:
- 修复思路: [简要说明]
- 预估时间: [小时/天]
- 所需技能: [技术要求]
- 测试要点: [需要测试的场景]
```

## 输出格式

分析报告需要包含：
1. **问题汇总表** - 所有问题及其评分
2. **优先级排序列表** - 按优先级排序
3. **修复建议** - 每个问题的修复思路
4. **工作量评估** - 预估总工时
5. **风险提示** - 修复过程中可能的风险

### 输入
- 来自 `bug-detection` 技能的排查报告

### 输出
- 分析报告 → 传递给 `bug-fix-planner` 技能

### 触发条件
- Bug 排查报告生成后自动触发
- 或手动触发: "使用 bug-analysis 技能分析报告"

---

**分析原则**: 客观准确、数据驱动、优先级清晰
