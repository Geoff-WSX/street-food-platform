# 小边技能工作流

## 技能概述
这是小边的完整技能链，用于排查、审核、解决和验证项目中的 Bug 和问题。

## ⚡ 自动触发机制

部分技能会在特定条件下**自动触发**，无需用户明确调用：

| 技能 | 自动触发条件 |
|------|-------------|
| **code-review-loop** | 使用 Edit/Write 修改文件后、功能开发完成、Bug 修复完成 |
| **simplify** | 代码完成后、用户要求优化时 |

**示例**：
```bash
# 当你执行以下操作时，code-review-loop 会自动启动：
1. Edit/Write 工具修改文件 → 自动审查
2. 完成功能开发 → 自动审查
3. 修复 Bug 完成 → 自动审查
```

## 技能文件说明

### 1. bug-detection.md - Bug 排查技能
**职责**: 定期排查项目中的问题

**工作内容**:
- 全面扫描前端、后端、代码质量
- 识别 Bug 和不合理设计
- 记录问题详情
- 生成问题列表

**输出**: Bug 排查报告（问题列表）

### 2. bug-review.md - Bug 审核技能
**职责**: 审核问题并给出解决方案

**工作内容**:
- 分析问题可行性
- 评估影响范围
- 设计解决方案
- 确定优先级

**输出**: 解决方案（修复方案、实施步骤）

### 3. bug-solution.md - Bug 解决技能
**职责**: 按照方案实际修复问题

**工作内容**:
- 执行代码修改
- 进行本地测试
- 提交修复代码
- 编写修复报告

**输出**: 修复报告（修改内容、测试结果）

### 4. bug-verification.md - Bug 验证技能
**职责**: 验证修复是否成功

**工作内容**:
- 执行功能验证
- 进行回归测试
- 检查性能指标
- 生成验证报告

**输出**: 验证报告（验证结果、最终状态）

## 快速开始

### 使用方式1：完整流程
```
1. 调用 bug-detection 技能排查问题
2. 将问题列表交给 bug-review 审核
3. 将解决方案交给 bug-solution 执行
4. 将修复结果交给 bug-verification 验证
5. 如果验证失败，返回步骤1
```

### 使用方式2：单步执行
```
根据需要单独调用某个技能：
- 只排查: 使用 bug-detection
- 只审核: 使用 bug-review + 问题列表
- 只修复: 使用 bug-solution + 解决方案
- 只验证: 使用 bug-verification + 修复信息
```

## 技能配合示例

### 示例1：修复白屏问题
```markdown
## 步骤1: 排查问题
调用: bug-detection
范围: 前端页面
发现: ReportsPage 在非审核员访问时白屏

## 步骤2: 审核方案
调用: bug-review
输入: 白屏问题描述
输出: 添加权限检查的解决方案

## 步骤3: 执行修复
调用: bug-solution
输入: 解决方案
修改: src/pages/ReportsPage.tsx
添加: 权限检查逻辑

## 步骤4: 验证修复
调用: bug-verification
输入: 修复报告
测试: 不同角色访问页面
结果: ✅ 验证通过
```

### 示例2：性能优化
```markdown
## 步骤1: 排查问题
调用: bug-detection
范围: 后端API

优化: 使用 include 减少查询

## 步骤4: 验证修复
调用: bug-verification

测试: API响应时间
结果: ✅ 性能提升74%
```

1. **技能顺序**: 按照排查→审核→解决→验证的顺序执行
2. **闭环管理**: 验证失败必须返回重新排查
3. **文档记录**: 每一步都要生成相应文档
4. **质量保证**: 确保每一步的质量后再进入下一步
5. **持续改进**: 根据实际情况优化技能内容
