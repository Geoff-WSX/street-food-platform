# 项目结构审查技能

## 技能概述
全面审查项目结构是否合理，包括目录组织、文件命名、依赖关系、代码复用等方面。

## 审查维度

### 一、目录结构评估

#### 1.1 分层清晰度
- **评估标准**: 项目是否有清晰的分层架构
- **检查点**:
  - 前端/后端是否分离
  - 页面/组件/工具是否分类明确
  - 业务逻辑与UI是否分离

#### 1.2 命名规范
- **评估标准**: 文件和目录命名是否一致、语义化
- **检查点**:
  - 是否遵循统一命名约定
  - 文件名是否清晰表达用途
  - 是否避免缩写和模糊命名

#### 1.3 文件组织
- **评估标准**: 文件组织是否便于查找和维护
- **检查点**:
  - 相关文件是否就近放置
  - 是否存在循环依赖
  - 深层嵌套是否过多

### 二、依赖关系评估

#### 2.1 模块依赖
- **评估标准**: 模块间依赖是否清晰、单向
- **检查点**:
  - 是否存在循环依赖
  - 依赖方向是否合理
  - 是否存在不必要的依赖

#### 2.2 包依赖
- **评估标准**: 第三方依赖是否必要、版本是否合理
- **检查点**:
  - 是否有未使用的依赖
  - 是否有重复功能的依赖
  - 是否存在安全漏洞的包

### 三、代码复用评估

#### 3.1 组件复用
- **评估标准**: 组件是否合理复用，避免重复代码
- **检查点**:
  - 是否存在相似但未抽取的组件
  - 组件职责是否单一
  - 组件粒度是否适中

#### 3.2 工具函数复用
- **评估标准**: 工具函数是否集中管理、合理复用
- **检查点**:
  - 是否存在重复的工具函数
  - 工具函数分类是否清晰
  - 是否有未使用的工具函数

### 四、架构设计评估

#### 4.1 状态管理
- **评估标准**: 状态管理方案是否合理
- **检查点**:
  - 状态管理方式是否统一
  - 全局状态是否过多
  - 本地状态是否合理使用

#### 4.2 API设计
- **评估标准**: API设计是否RESTful、接口是否清晰
- **检查点**:
  - 接口命名是否规范
  - 请求/响应格式是否统一
  - 错误处理是否完善

#### 4.3 数据模型
- **评估标准**: 数据模型设计是否合理
- **检查点**:
  - 数据表设计是否规范
  - 关系设计是否合理
  - 是否有冗余字段

### 五、配置管理评估

#### 5.1 环境配置
- **评估标准**: 环境变量管理是否规范
- **检查点**:
  - 是否区分开发/生产环境
  - 敏感信息是否正确处理
  - 配置是否集中管理

#### 5.2 构建配置
- **评估标准**: 构建配置是否优化
- **检查点**:
  - 构建速度是否合理
  - 打包体积是否优化
  - 是否有构建优化配置

### 六、文档完整性

#### 6.1 代码注释
- **评估标准**: 关键代码是否有注释
- **检查点**:
  - 复杂逻辑是否有说明
  - 函数是否有JSDoc
  - API是否有文档

#### 6.2 README和文档
- **评估标准**: 项目文档是否完整
- **检查点**:
  - README是否清晰
  - API文档是否完整
  - 部署文档是否存在

## 审查流程

### 步骤1: 收集信息
```
1. 列出项目目录结构
2. 检查 package.json 依赖
3. 查看主要配置文件
4. 抽样检查关键代码文件
```

### 步骤2: 分析评估
```
1. 按维度逐项评估
2. 记录发现的问题
3. 评估问题严重程度
4. 提出改进建议
```

### 步骤3: 生成报告
```
1. 总结整体评分
2. 列出具体问题
3. 给出优先级建议
4. 提供改进方案
```

## 使用方式

### 命令调用
```
/skill 使用项目结构审查技能分析当前项目
```

### 审查重点
- **小型项目**: 目录结构、命名规范、代码复用
- **中型项目**: 上述 + 架构设计、依赖管理
- **大型项目**: 全部维度

## 常见问题与建议

### 问题1: 目录结构混乱
**症状**: 文件随意放置，难以查找
**建议**: 按功能/类型重新组织目录

### 问题2: 循环依赖
**症状**: A依赖B，B又依赖A
**建议**: 提取共享逻辑到独立模块

### 问题3: 重复代码
**症状**: 相似代码出现在多处
**建议**: 抽取公共组件或工具函数

### 问题4: 依赖过多
**症状**: package.json 中有大量未使用的依赖
**建议**: 清理无用依赖，考虑使用轻量级替代

### 问题5: 配置分散
**症状**: 配置散落在各文件中
**建议**: 集中管理配置，使用环境变量

### 问题6: 缺少文档
**症状**: 新成员难以理解项目
**建议**: 完善 README、API 文档和代码注释
