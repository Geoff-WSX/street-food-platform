# 需求合理性验证技能

## 技能概述
在实施新功能或修改功能前，验证需求的合理性，避免浪费开发资源。

## 工作流程

### 第一步：需求理解
1. 明确需求的核心目标
2. 识别需求的受益用户
3. 确定需求的优先级

### 第二步：合理性评估
从以下维度评估需求：

#### 1. 价值维度
- **用户价值**: 是否解决真实痛点？
- **业务价值**: 是否带来商业收益？
- **技术价值**: 是否提升技术能力？

#### 2. 可行性维度
- **技术可行性**: 现有技术栈能否实现？
- **资源可行性**: 人力/时间是否充足？
- **成本可行性**: 投入产出比是否合理？

#### 3. 影响维度
- **兼容性**: 是否影响现有功能？
- **性能**: 是否带来性能负担？
- **维护性**: 是否增加维护成本？

#### 4. 一致性维度
- **产品定位**: 是否符合产品方向？
- **用户体验**: 是否保持体验一致性？
- **技术架构**: 是否符合技术规范？

### 第三步：判断结论

#### ✅ 通过条件（满足以下至少3项）
1. 解决明确的用户痛点
2. 技术可行且成本合理
3. 不破坏现有功能
4. 符合产品发展方向

#### ❌ 驳回条件（满足以下任一项）
1. 需求描述不清晰
2. 技术不可行或成本过高
3. 严重破坏现有架构
4. 与产品定位冲突
5. 存在更优的替代方案

#### ⚠️ 待完善条件
1. 需求有价值但描述不清
2. 技术可行但需要详细设计
3. 有潜在风险但可规避

## 输出格式

### 通过结论
```markdown
## 需求验证结果: ✅ 通过

### 需求概述
[简述需求内容]

### 评估结论
- 用户价值: ✅ [说明]
- 技术可行性: ✅ [说明]
- 影响评估: ✅ [说明]
- 一致性: ✅ [说明]

### 建议
[实施建议]
```

### 驳回结论
```markdown
## 需求验证结果: ❌ 驳回

### 需求概述
[简述需求内容]

### 驳回原因
- [原因1]
- [原因2]

### 改进建议
[如何改进需求]
```

### 待完善结论
```markdown
## 需求验证结果: ⚠️ 待完善

### 需求概述
[简述需求内容]

### 待补充内容
- [需要补充的信息1]
- [需要补充的信息2]

### 潜在风险
- [风险1] - [规避方案]
```

## 使用示例

### 示例1: 合理需求
**输入**: "添加用户搜索功能，支持按用户名搜索"
**输出**: ✅ 通过 - 核心功能，用户需求明确，技术可行

### 示例2: 不合理需求
**输入**: "开发一个AI自动生成美食图片的功能"
**输出**: ❌ 驳回 - 技术复杂度高，成本过大，非核心功能

### 示例3: 待完善需求
**输入**: "优化搜索"
**输出**: ⚠️ 待完善 - 需明确优化目标（速度、准确度、功能？）
