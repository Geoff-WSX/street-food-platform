# Bug 修复方案规划技能

## 技能定位
你是小边的技术规划专家，负责基于 Bug 分析报告制定详细的修复方案，分配任务，规划执行步骤。

## 规划流程

### 第一步：接收分析报告
```
读取分析报告 → 理解问题优先级 → 确定修复策略
```

### 第二步：制定修复策略

#### 修复原则
1. **优先级优先** - P0 > P1 > P2 > P3
2. **依赖关系** - 先修复被依赖的问题
3. **风险控制** - 高风险问题需要回滚方案
4. **效率优先** - 同类问题批量处理

#### 修复策略分类

| 策略 | 适用场景 | 说明 |
|------|----------|------|
| **立即修复** | P0 问题 | 阻塞其他功能或严重影响用户 |
| **快速修复** | P1 问题 | 影响体验但不阻塞功能 |
| **计划修复** | P2 问题 | 下个迭代版本修复 |
| **延后处理** | P3 问题 | 有时间时处理 |

### 第三步：任务分解

对每个需要修复的问题，分解为可执行的任务：

```markdown
### 任务: [BUG-XXX] 修复 [问题标题]

**任务信息**:
- 任务ID: TASK-BUG-XXX
- 关联问题: BUG-XXX
- 优先级: P0/P1/P2/P3
- 预估工时: X 小时

**执行步骤**:
1. [步骤1] - 预计 X 分钟
2. [步骤2] - 预计 X 分钟
3. [步骤3] - 预计 X 分钟

**所需文件**:
- 需要修改: [文件路径]
- 需要新建: [文件路径]
- 需要删除: [文件路径]

**代码修改**:
- 修改位置: [文件:行号]
- 修改前: [代码片段]
- 修改后: [代码片段]

**测试验证**:
- [ ] 单元测试通过
- [ ] 功能测试通过
- [ ] 回归测试通过
- [ ] 无新问题引入

**风险控制**:
- 风险点: [可能的问题]
- 回滚方案: [如何回滚]
- 验证方法: [如何验证修复]
```

```markdown
# Bug 修复执行计划

## 计划概览
- 计划时间: [开始时间] - [结束时间]
- 总任务数: X 个
- 总预估工时: X 小时
- 执行方式: 自动化 Agent / 人工审核

## 任务分组

### 第一批: P0 紧急修复 (立即执行)
**预估工时**: X 小时
**任务列表**:
1. [TASK-BUG-001] - X 小时
2. [TASK-BUG-002] - X 小时

执行顺序:
1. TASK-BUG-001 → 验证 → TASK-BUG-002 → 验证

### 第二批: P1 重要修复 (本批次执行)
**预估工时**: X 小时
**任务列表**:
1. [TASK-BUG-004] - X 小时
2. [TASK-BUG-005] - X 小时

### 第三批: P2 普通修复 (下批次执行)
**预估工时**: X 小时
**任务列表**:
[同上格式]

## 执行时间表

| 时间 | 任务 | 负责者 | 状态 |
|------|------|--------|------|
| 09:00-10:00 | TASK-BUG-001 | BugFixAgent | 待执行 |
| 10:00-11:00 | TASK-BUG-002 | BugFixAgent | 待执行 |

## 验证计划
- 修复前测试: [记录当前状态]
- 修复中验证: [每个步骤后的验证]
- 修复后测试: [完整回归测试]
- 回归测试: [确保无新问题]

## 风险控制
- 高风险任务: [列出]
- 回滚预案: [说明]
- 紧急联系人: [如有问题找谁]

## 下一步
提交给 bug-fix-agent 执行修复
```

## 任务分配模板

### 单个任务详细规划
```markdown
## 任务: TASK-BUG-XXX

### 基本信息
- **任务ID**: TASK-BUG-XXX
- **关联问题**: BUG-XXX
- **任务标题**: [简短描述]
- **优先级**: P0/P1/P2/P3
- **状态**: 待执行/执行中/已完成/已验证

### 执行计划

#### 步骤 1: 准备工作
**预估时间**: 5 分钟
**操作内容**:
1. 创建新分支: `fix/bug-xxx`
2. 备份需要修改的文件
3. 记录当前状态

**验证点**: 分支创建成功

#### 步骤 2: 代码修改
**预估时间**: X 分钟
**操作内容**:
1. 打开文件: [路径]
2. 定位代码: [行号]
3. 修改代码:
```diff
- 修改前
+ 修改后
```

**验证点**: 代码修改正确

#### 步骤 3: 测试验证
**预估时间**: 10 分钟
**操作内容**:
1. 运行服务
2. 测试功能: [测试步骤]
3. 检查日志: [检查项]
4. 验证修复: [验证方法]

**验证点**: 功能正常，无新问题

#### 步骤 4: 提交记录
**预估时间**: 5 分钟
**操作内容**:
1. 提交代码: git commit
2. 记录日志: [日志文件]
3. 更新状态: 已完成

**验证点**: 提交成功

### 修改详情

**文件 1**: [文件路径]
**修改位置**: 第 X 行
**修改类型**: 修改/新增/删除

**修改前**:
```typescript
// 代码
```

**修改后**:
```typescript
// 代码
```

### 测试计划

**测试用例 1**: [场景描述]
- 前置条件: [条件]
- 执行步骤: [步骤]
- 预期结果: [结果]
- 实际结果: [待填写]

**测试用例 2**: [同上]

### 风险控制

**可能风险**:
1. [风险1] - 影响: [说明] - 概率: [高/中/低]
2. [风险2] - 同上

**应对措施**:
1. [措施1]
2. [措施2]

**回滚方案**:
```bash
# 回滚命令
git revert <commit-hash>
# 或
git checkout <previous-branch>
```

### 完成标准
- [ ] 代码修改完成
- [ ] 本地测试通过
- [ ] 无新问题引入
- [ ] 代码已提交
- [ ] 日志已记录
```

## 输出格式

执行计划需要包含：
1. **任务列表** - 按优先级排序
2. **时间安排** - 预估时间表
3. **执行步骤** - 每个任务的详细步骤
4. **验证计划** - 如何验证修复
5. **风险预案** - 可能的问题和应对

- 来自 `bug-analysis` 技能的分析报告

- 执行计划 → 传递给 `bug-fix-agent` 执行
