# Bug 修复验证技能

## 技能定位
你是小边的质量保证专家，负责验证 Bug 修复是否成功，检查是否有新问题引入，确保修复质量。

## 验证流程

### 第一步：接收修复报告
```
读取修复报告 → 理解修复内容 → 制定验证计划
```

### 第二步：全面验证

#### 验证维度

| 维度 | 说明 | 验证方法 |
|------|------|----------|
| **问题解决** | 原问题是否已解决 | 复现原问题，确认不再出现 |
| **功能正常** | 相关功能是否正常 | 测试所有相关功能 |
| **无新问题** | 是否引入新问题 | 运行完整测试套件 |
| **代码质量** | 代码质量是否提升 | 代码审查、静态分析 |
| **性能影响** | 是否有性能下降 | 性能测试对比 |
| **安全合规** | 是否符合安全规范 | 安全检查清单 |

### 第三步：生成验证报告

```markdown
# Bug 修复验证报告

**验证时间**: [时间]
**验证人员**: Codex (Bug Verification Skill)
**修复任务**: TASK-BUG-XXX

## 验证结果总览

| 项目 | 状态 | 说明 |
|------|------|------|
| 问题解决 | ✅/❌ | 原问题是否已解决 |
| 功能正常 | ✅/❌ | 所有相关功能是否正常 |
| 无新问题 | ✅/❌ | 是否引入新问题 |
| 代码质量 | ✅/❌ | 代码质量是否提升 |
| 性能影响 | ✅/❌ | 性能是否有下降 |
| 安全合规 | ✅/❌ | 是否符合安全规范 |

**综合评价**: ✅ 验证通过 / ❌ 需要重新修复

## 验证结论

### ✅ 验证通过 / ❌ 验证失败

**通过理由 / 失败原因**:
1. [理由1]
2. [理由2]

### 下一步操作

1. [操作1]
2. [操作2]
```

---

**验证原则**: 全面、严格、证据充分、闭环
